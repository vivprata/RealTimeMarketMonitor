1 — Simulator (Producer)

ComponentDetail
simulator/engine.pyStateless price engine. Random walk per symbol using annual volatility from config/symbols.json. Supports scenarios: NORMAL, RALLY, SELLOFF, SHOCK.
run_simulator.pyCLI entry point. On startup: (1) burst-produces warmup ticks (back-dated, burst speed) to pre-fill Flink's 5-min window; (2) calls arm_msft_anomaly() immediately after; (3) enters live tick loop at ~1 tick/sec per symbol.
MSFT Anomalyarm_msft_anomaly() pins MSFT at –6.3% below its post-warmup anchor price with 3.4× volume, held indefinitely. MSFT annual vol = 0.199 → daily σ = 1.25% → –6.3% = 5.03σ.
INJECT SHOCK buttonTriggers a separate shock on IBM (or any symbol): –5.5% drop over 12 ticks, 600-tick hold, then recovery. Independent of the MSFT permanent anomaly.

3 — Flink SQL (market_signals computation)

File: flink/01_market_signals.sql — run once in Confluent Cloud → Flink → SQL Workspace. Must be manually resumed if it stops (free trial auto-stops ~every 12h).
FieldComputation
price_change_pct(current_price − oldest price in 5-min rolling window) / oldest × 100. Gives full shock magnitude.
volume_ratiocurrent_volume / avg volume in 30-sec rolling window. Short window so a burst spike registers immediately.
statusRule: HIGH_VOLUME_DROP if drop < –3% AND volume > 2×; SIGNIFICANT_DROP if ≤ –5%; DOWN if ≤ –3%; UP if ≥ +3%; else NORMAL.

6 — Dashboard Background Consumer (market_data.py)

ComponentDetail
MarketStateThread-safe in-memory store. Holds latest price, volume, bid/ask, tick history (last 600), and latest Flink signal per symbol.
ConsumerThreadDaemon thread created once per Streamlit session (@st.cache_resource). Phase 1: drains historical backlog (portfolio + signals replay). Phase 2: live poll loop.
snapshot()['rows']Per-symbol dict with: price, change_pct (vs first-seen price), vol_ratio, plus Flink-authoritative flink_change_pct, flink_vol_ratio, flink_status (None until Flink signals arrive).
Topics consumedmarket_ticks (OFFSET_END), market_signals (OFFSET_BEGINNING), portfolio_positions (OFFSET_BEGINNING)

7 — Dashboard Pages

#PageData sourcesKey logic
1 Live Market Monitor Kafka market_ticks (live) Reads MarketState.snapshot() directly. Ticks → price grid + sparklines. INJECT SHOCK button calls simulator endpoint.
2 Historical Analysis S3 Parquet hive_catalog Presto queries against historical_prices + historical_risk_metrics. No streaming dependency — unaffected by Iceberg breakage.
3 Anomaly Detection Kafka market_signals (live) + S3 historical_risk_metrics score_anomalies_from_kafka(): takes flink_change_pct (or local change_pct fallback) from the in-memory consumer, joins with S3 volatility in Python. No Iceberg/Tableflow. MSFT shows ≥5σ permanently.
4 Portfolio Rebalancing Kafka live prices + S3 historical_prices + portfolio_positions Presto query against S3 hive tables for 6m/1y returns; live prices from MarketState.snapshot(). No Iceberg/Tableflow. Position weights computed in Python.

8 — Anomaly Scoring Formula

daily_σ % = annual_volatility / √252 × 100
anomaly_sigma = |price_change_pct| / daily_σ % (capped at 10)

MSFT example: annual vol = 0.199 → daily σ = 1.254% → change = –6.3% → 5.03σ 🚨
Threshold for anomaly flag: ≥ 1.5σ (configurable via ANOMALY_SIGMA_THRESHOLD)
